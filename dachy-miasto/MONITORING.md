# Измерения установок и учебный стенд

Экран «Мониторинг» обрабатывает записи в браузере. Он не запрашивает доступ к аккаунтам владельцев и не отправляет файлы на сервер. Сохраните запись перед закрытием страницы. Настоящая городская установка пока не подключена.

## Три вида данных

- Прогнозы крыш остаются на экране «План». Это расчёт по MONIT-AIR, а не измерения оборудования.
- Импортированный JSON — запись указанного периода. Текущий статус установки по ней не устанавливается. Координаты PV из такой записи можно показать синим маркером; это сведения из файла пользователя, не независимая проверка объекта.
- USB-стенд получает реальные показания через Web Serial. Метка «живые» появляется при приёме данных за последние 10 секунд; при остановке потока текущая мощность становится неизвестной. После отключения сохранённые показания остаются записью.

Кнопка «Открыть учебный пример» создаёт искусственный 90-секундный эксперимент: свет → тень → восстановление. Он явно помечен, не имеет координат и не изображает настоящую установку Кракова.

## Формат импорта JSON

```json
{
  "schemaVersion": 1,
  "mode": "recording",
  "installation": {
    "id": "owner-provided-id",
    "name": "Название установки",
    "kind": "pv",
    "measurementPoint": "ac-output",
    "sourceUrl": "https://example.org/owner-provided-source",
    "location": { "latitude": 50.05, "longitude": 19.95 }
  },
  "samples": [
    { "timestamp": "2026-10-26T10:00:00Z", "powerW": 1000, "selfConsumedPowerW": 600, "exportPowerW": 400 },
    { "timestamp": "2026-10-26T10:00:10Z", "powerW": 1100, "selfConsumedPowerW": 650, "exportPowerW": 450 }
  ]
}
```

Это пример структуры с условными числами и координатами, не запись существующей установки. Для реального импорта замените их сведениями владельца. Файл — максимум 5 МБ, от 2 до 20 000 показаний. Времена должны строго возрастать и содержать часовой пояс (`Z` или `+01:00`). Мощность задаётся в ваттах; отрицательные и нечисловые значения отклоняются. `mode: live` для файла запрещён. Для учебного стенда используйте `kind: bench`, `measurementPoint: dc-load` без координат.

`sourceUrl` и `location` необязательны. `selfConsumedPowerW` и `exportPowerW` также необязательны: это именно потоки энергии от PV, а не общий расход здания или суммарный экспорт с аккумулятором. Их сумма не должна превышать генерацию. Если источник показывает только инверторную мощность, эти поля нужно оставить отсутствующими, а не подставлять предположения.

Энергия рассчитывается методом трапеций между соседними показаниями. По умолчанию интервалы длиннее 30 секунд исключаются и считаются пропусками. Для выгрузки с другим известным шагом задайте соответствующий предел; увеличение предела не восстанавливает отсутствующие измерения. Счётчики относятся только к наблюдаемым интервалам, не ко всему сроку эксплуатации. Время и график отображаются в часовом поясе компьютера.

Денежный эффект доступен только для PV при полном наборе потоков в учтённых интервалах и двух введённых ценах:

`собственное потребление PV × цена замещённой покупки + отдача PV в сеть × цена продажи`.

Цены применяются как постоянные ко всему периоду записи. Это оценка до расходов и без проверки счетов; она не является подтверждённой экономией, расчётом окупаемости или юридической моделью расчётов с поставщиком. Для стенда денежный эффект не рассчитывается.

## Городской слой OZE

На карте «Плана» можно включить городской слой OZE. Источник: [каталог WS instalacje OZE](https://msip.krakow.pl/dataset/2842), [REST-сервис](https://msip.um.krakow.pl/arcgis/rest/services/JP/Instalacje_OZE_2023/MapServer). В проверенном описании сервиса слой `1` относится к 2024 году. Каталог упоминает данные разных лет, включая 2025; приложение не выдаёт слой 2024 за срез 2025.

Запрашиваются изображения слоя, без копирования записей в локальный набор. OZE включает не только PV, но также коллекторы и тепловые насосы. Совпадение с крышей не меняет её статус наличия PV, собственность или допуск к подбору. Изображение реестра не содержит текущей выработки. Загрузка зависит от сети и сервиса MSIP; недоступность слоя показана в интерфейсе. Отдельные объекты реестра в этой версии не идентифицируются по клику; синий маркер импортированной PV открывает её запись мониторинга.

## Минимальный стенд без аккумулятора

Панель → INA219 → известная DC-нагрузка. Контроллер Nano/Uno получает питание от USB ноутбука; панель питает только демонстрационную нагрузку. Измеряется мощность на нагрузке после шунта INA219, не мощность всего стенда и не максимум мощности панели.

Подключение для Arduino Nano/Uno на ATmega328P:

| Контакт | Подключение |
| --- | --- |
| Плюс панели | INA219 VIN+ |
| INA219 VIN− | Плюс нагрузки |
| Минус нагрузки | Минус панели и общий GND |
| INA219 GND | GND Arduino и минус панели |
| INA219 VCC | 5V Arduino |
| INA219 SDA | A4 Arduino |
| INA219 SCL | A5 Arduino |

Для панели 6 В / 3 Вт подходит демонстрационная резистивная нагрузка порядка 12–15 Ом с номиналом мощности 10 Вт. Это ориентир для опыта, не подбор оптимальной рабочей точки; резистор может нагреваться, закрепите его на подходящей негорючей опоре. До подачи питания проверьте полярность и разводку конкретного модуля. Небольшие площадки панели и комплектные штыри INA219 могут требовать пайки.

В Arduino IDE установите библиотеку **Adafruit INA219** с её зависимостями и загрузите `firmware/solar-bench/solar-bench.ino`. Скетч подготовлен для Nano/Uno ATmega328P; на оборудовании ещё не проверен. Закройте Serial Monitor Arduino IDE, откройте приложение в настольном Chrome/Edge на localhost и нажмите «Подключить USB-стенд». Выберите COM-порт.

Формат протокола: одна JSON-строка в секунду при 115200 бод:

```json
{"voltageV":5.2,"currentA":0.08}
```

Приложение вычисляет `powerW = voltageV × currentA` и ставит время получения на ноутбуке. Контроллер должен передавать текущие измерения непрерывно; этот протокол не предназначен для передачи накопленного архива без временных меток. Неверные строки пропускаются. Обратный ток не превращается в положительную генерацию. При 20 000 показаний запись прекращает пополняться: сохраните её и начните новую сессию.

Для опыта: устойчивое освещение → тень от карточки → убрать карточку. Мощность 3 Вт на этикетке не обещает 3 Вт в аудитории. Проверьте стенд при ожидаемом освещении заранее; подготовьте сохранённую реальную запись как резерв. Свет от лампы демонстрирует реакцию панели, но не доказывает энергетическую выгоду с учётом потребления самой лампы.

Основания: [Web Serial в Chrome](https://developer.chrome.com/docs/capabilities/serial), [руководство INA219](https://learn.adafruit.com/adafruit-ina219-current-sensor-breakout/overview), [даташит TI INA219](https://www.ti.com/product/INA219).
