# Dachy Miasta 0.7

Проект использует открытые данные для объяснимого выбора крыш под PV и наглядного сравнения конфигураций. Реальная установка, сбор показаний и USB не входят в текущий объём. Пользовательские экраны: **«Как читать» → «План» → «Симуляция» → «Данные» → «Методика»**.

## Что делает приложение

**План:** выбирает набор целых установок под бюджет по исторической модели MONIT-AIR. Параметры, ограничения мощности, фильтры, три стратегии, чувствительность, кривая бюджета и объяснения сохранены. При базовых значениях: 10 крыш, 968,495 МВт·ч/год, 4 993 680 zł. Это сценарий для дальнейшей проверки, не готовый проект.

**Симуляция:** размещает модули в контуре выбранного здания MSIP, показывает объёмный эскиз, позволяет менять наклон, азимут, месяц, профиль дня, ручные сценарии тени и снега. Можно вращать камеру, просматривать сутки, сравнивать месяцы, год и таблицу ориентаций. Основа климата — локальный PVGIS TMY из 8 760 часов.

**Данные:** поиск, сортировка, фильтры, источники и очередь проверки 15 объектов. Адреса, участки и охранные сигналы — кандидаты для подтверждения. Городской слой OZE остаётся открытым картографическим источником, без подключения к устройствам.

**Как читать:** смысл, источник и формула каждого типа чисел; исходная площадь, её округление, доля под модули, предел мощности и промежуточные результаты выбранной крыши. Пояснения доступны и по `?`.

## Запуск и команды

Node.js 22+, без npm-зависимостей:

```sh
npm run dev
```

Открыть http://127.0.0.1:4173/. Другой порт: `npm run dev -- --port 4174`. Открывать через HTTP, поскольку используются модули, Worker и JSON.

| Команда | Назначение |
| --- | --- |
| `npm test` | Модель, геометрия, климат, раскладка, оптимизация, экспорт и RU/PL |
| `npm run audit:data` | Повторить сверку исходных площадей, излучения, геометрии и SHA256 |
| `npm run docs:numbers` | Обновить справочники RU/PL из определений интерфейса |
| `npm run build` | Создать чистую статическую сборку `dist/` |
| `npm run climate` | Получить новый TMY PVGIS; нужен интернет |
| `npm run sources` | Обновить геометрию и солнечные поля MSIP |
| `npm run context` | Адреса, районы и культурные парки |
| `npm run registers` | EGiB, собственность участков, охрана и OZE |

| `npm run review` | Пересоздать очередь ручной проверки |
| `npm run benchmark` | Повторить сравнение оптимизатора на пилоте |

Браузерная проверка при работающем сервере:

```sh
node scripts/browser-qa.mjs --offline --url http://127.0.0.1:4174/
```

Проверяет также отсутствие мониторинга, недоступный климат, сезоны, угол, камеру, снег/тень, эскиз, экспорт, маркер, мобильную версию и печать. `--offline` отключает внешние тайлы карты, сохраняя локальные данные и расчёты. Скриншоты, PDF и отчёт находятся в `.preview/`.

Проверка 0.7: 47 автоматических тестов, аудит исходного пилота и чистая сборка прошли; 45 пунктов Chrome QA — без ошибок JavaScript. Проверки практического оборудования удалены вместе с исключённым функционалом.

## Как пользоваться симуляцией

1. В «Плане» выбрать крышу и нажать «Разместить панели на этой крыше».
2. Задать наклон 0–60° и направление. Азимут отсчитывается от севера: N=0°, E=90°, S=180°, W=270°.
3. Сравнить зиму и лето, P10/P50/P90. Это профили дней TMY, а не вероятность или прогноз завтрашней погоды.
4. Проверить число поместившихся модулей. Отступы и просвет рядов редактируются в дополнительных параметрах. Мощность и энергия считаются по размещённому числу, которое может быть меньше исходного.
5. В таблице сравнить одну и ту же мощность 1 кВтп за год или за выбранный месяц; нажать ячейку для применения варианта.
6. Сохранить JSON с климатом, координатами модулей, допущениями и расчётом или CSV профиля дня.

День открывается в 12:00, чтобы эскиз был виден. Ползунок времени и ускорение управляют просмотром. Смена физических параметров пересчитывает весь сценарий, без смешивания разных условий в историю.

## Архитектура

| Файл / папка | Роль |
| --- | --- |
| `src/core/model.js` | Модель годового потенциала и критерии плана |
| `src/core/optimizer.js`, `src/worker.js` | Подбор, сравнение, чувствительность и бюджеты |
| `src/core/provenance.js` | Проверка исходных полей и происхождение расчётов |
| `src/core/climate.js` | TMY, солнце, наклонное излучение, температура и энергия |
| `src/core/layout.js` | Метрическая проекция и размещение прямоугольников в контуре с отверстиями |
| `src/core/simulation.js` | Состояние эскиза, погода/месяц, просмотр и экспорт |
| `src/roof-scene.js` | Объёмная SVG-проекция контура и модулей |
| `src/simulation-view.js` | Настройки, визуализация, графики, сравнение и следующий план действий |
| `src/core/oze.js` | Открытый городской картографический слой OZE |
| `src/number-guide.js`, `src/climate-number-guide.js` | Справочник показателей RU/PL |
| `data/krakow-climate.json` | Зафиксированный TMY PVGIS с метаданными и SHA256 ответа |

Данные не отправляются на сервер. Сохранённые параметры и варианты плана остаются в браузере; эскиз хранится в памяти до закрытия страницы, для сохранения нужен экспорт.

## Ограничения

Полезная площадь MSIP — модельное поле, а не обследованное свободное место. Все 927 значений пилота сверены с сохранённым источником; правило почти постоянной доли около 79,9% площади здания не подтверждено.

Объёмный вид — эскиз плоской крыши. Высота 6 м, размеры модуля, отступы, просвет, коэффициенты температурной модели и потери — допущения. Не моделируются существующие скаты, надстройки, межрядные тени, несущая способность, конкретный инвертор и подключение. Снег не определяется по зимнему месяцу.

«План» и «Симуляция» используют разные модели излучения; новая ориентация не применяется повторно к историческому излучению MONIT-AIR. Результаты эскиза не переписывают городской план автоматически. Бюджет и экономические показатели остаются отдельным сценарием плана.
