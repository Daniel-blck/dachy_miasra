# Dachy Miasta

Работающий локальный прототип для конкурса Open Data App Kraków. Приложение подбирает набор крыш под заданный бюджет, сравнивает три стратегии и показывает, насколько результат устойчив к изменению допущений.

Интерфейс по умолчанию на польском — для конкурса; переключатель **PL / RU** вверху сохраняет выбор языка в браузере. Аудит логики и интерфейса и статус его пунктов — [AUDIT.md](../AUDIT.md). Карта показывает улицы OpenStreetMap и контуры MSIP, поддерживает колесо мыши, перетаскивание и приближение выбранной крыши.

## Объяснение прогноза и мониторинг (ветка Daniel-blck)

В версии 0.4 числовое объяснение связывает солнечное излучение с прогнозом электричества, мощностью и стоимостью выбранной крыши. В «Методике» описаны измерения и учёт наклона/теней в MONIT-AIR, а также сравнение большой крыши и более солнечного метра.

Новый экран «Мониторинг» принимает JSON записей, показывает график мощности и энергию без заполнения длинных пропусков. Доступны явно помеченный искусственный пример и чтение USB-стенда через Web Serial. Для координат импортированной PV появляется отдельный синий маркер. Денежный эффект требует измеренных потоков собственного потребления/экспорта и введённых цен. Настоящая городская установка пока не подключена; прошивка на оборудовании не проверена.

На карте можно включить сетевой городской слой OZE 2024 года: он включает PV, коллекторы и тепловые насосы, не содержит онлайн-выработки и не меняет допуск крыш к подбору. Его загрузка в текущей среде не проверена.

## Запуск

Нужен Node.js 22 или новее. Зависимостей для установки нет.

```powershell
cd C:\Users\klim3\Desktop\dachy_miasta\dachy-miasto
npm.cmd run dev
```

Открыть **http://127.0.0.1:4173/** в браузере. Завершить сервер — `Ctrl+C`.

Из родительской папки можно запустить `START_DACHY.cmd`. HTML следует открывать через сервер: браузер загружает JSON, ES-модули и Worker.

## Что проверить вручную

1. При стандартном сценарии 5 млн zł, пределе 150 кВтп и только городских участках в плане 10 крыш, около 968 МВт·ч/год, 578 т CO₂/год, около 5 160 zł на 1 МВт·ч/год; все 10 установок в классе 50–150 кВтп, все на участках гмины или повята.
2. Выбрать «Bez limitu»: план сократится до 4 крыш, крупнейшая даст около 61% выработки, появится предупреждение о концентрации. Сохранить оба варианта и сравнить их в таблице.
3. Снять «Tylko dachy na działkach miasta»: в план вернутся крыши с неизвестной собственностью участка, выработка вырастет примерно на 1%.
4. Изменить бюджет, стоимость монтажа или покрытие площади: список, кривая и сравнение пересчитаются.
5. Навести курсор на карту и прокрутить колесо; переместить карту мышью. «Все крыши» возвращает общий вид, «Выбранные» показывает объекты плана.
6. Нажать на крышу на карте или в списке. Карточка покажет адрес, назначение здания, участок и его собственника, освещённость относительно PVGIS, процедуру, охрану и чек-лист проверки. Исключить и восстановить объект.
7. В «Данных» выбрать фильтр «Wymagają pozwolenia konserwatora», отсортировать по удельной выработке, найти объект по адресу.
8. Открыть «Методика», проверить допущения, калибровку PVGIS, пороги процедур, реестры и источники.
9. Выгрузить CSV плана, очередь проверки или полный JSON сценария. «Отчёт PDF» открывает печать браузера: отчёт помещается на одну страницу A4.
10. Переключить RU / PL: расчёты и положение карты сохраняются.
11. Выбрать крышу и прочитать блок «Skąd pochodzi prognoza» / «Откуда берётся прогноз»: входные поля и коэффициенты должны совпадать с параметрами и результатом. В «Методике» посмотреть объяснение наклона и сравнение условных крыш.
12. В «Мониторинге» открыть учебный пример: видна подпись об искусственных данных, график реакции на тень, денежный эффект отсутствует. Сохранить JSON и загрузить его обратно: пример сохраняет происхождение.
13. Для реальной записи использовать формат из `MONITORING.md`. Проверить период, пропуски, денежный эффект только при наличии потоков и цен. Установка с координатами показывается отдельным синим маркером; клик открывает запись.
14. Включить городской слой OZE: он требует сети; при ошибке показывается сообщение. Не считать все объекты слоя фотоэлектрическими установками и не трактовать их как подключённые к мониторингу.

Параметры, исключения, сохранённые варианты и язык хранятся только в текущем браузере. «Сбросить параметры» восстанавливает исходный расчёт и возвращает исключённые объекты.

## Данные и границы версии

- Извлечены 927 записей из исходного HTML; сохранён SHA256 источника. Дата первоначального среза неизвестна.
- Для всех 927 идентификаторов получена геометрия из официального MSIP, преобразованная сервером в EPSG:4326. Значения годового излучения совпали с исходным пакетом.
- Официальный сервис содержит 118 594 записи и описан как MONIT-AIR Atlas 2016. Полный город в приложение не загружен.
- Адрес — ближайшая адресная точка MSIP (внутри контура или не дальше 30 м от него). Это кандидат для проверки, а не адрес из реестра зданий. Культурный парк определяется по пересечению контура крыши с границей парка; это сигнал о согласованиях, а не заключение консерватора.
- Пороги процедур (6,5 / 50 / 150 кВт) — ориентир для планирования. Каждая установка требует подтверждения у проектировщика, оператора сети и, для охраняемых объектов, у консерватора.
- Солнечные показатели и полезная площадь остаются значениями исследовательского пакета. В исходном пакете площадь округлена. Верификация геометрии не доказывает актуальность построек и установок.
- Собственность/управление зданием, охранный статус, несущая способность и наличие PV **не подтверждены**.
- Флаг зелёной кровли и название климатической инвестиции не являются инженерным заключением или доказательством установленной PV.
- Коэффициенты и затраты — изменяемый сценарий. Экономия денег, окупаемость, самопотребление, инженерная готовность и соответствие EED не заявляются. CO₂ — оценка замещения электроэнергии из сети, а не баланс выбросов здания.
- Карта использует Leaflet 1.9.4 и улицы OpenStreetMap. Для загрузки подложки нужен интернет; библиотека и данные крыш хранятся локально. При недоступности подложки контуры и расчёты продолжают работать.
- Срез и расчёты работают без MSIP и внешнего интернета. Условия дальнейшей публикации данных MSIP нужно проверить до внешнего размещения. На карте сохранена атрибуция OpenStreetMap.
- Панель с физическими датчиками не входит в основной объём проекта.

## Архитектура

```text
scripts/extract-reference.mjs     HTML → нормализованные записи + происхождение
scripts/fetch-msip.mjs            запросы к MSIP → геометрия + журнал верификации
scripts/fetch-context.mjs         адресные точки и культурные парки MSIP → data/roof-context.json
scripts/fetch-registers.mjs       EGiB, собственность участков, памятники, UNESCO, ВИЭ (ArcGIS REST MSIP) → data/roof-registers.json
scripts/fetch-pvgis.mjs           эталонная выработка PVGIS для Кракова → data/pvgis-reference.json
src/core/registers.js             группы собственности, сигналы охраны памятников, «земля города»
src/core/model.js                 физическая модель, предел мощности, процедуры, сводка плана
src/core/optimizer.js             стратегии, динамическое программирование, граница, кривая бюджета
src/core/geo.js                   EPSG:2178 → WGS84, точка в полигоне, расстояния
src/worker.js                     подбор, сценарии и кривая без блокировки интерфейса
src/app.js                        точка входа
src/controller.js                 состояние, события, Worker, сохранённые варианты, экспорты
src/views.js                      интерфейс и пояснения
src/i18n.js                       русские и польские тексты, читаемые названия зданий
src/map.js                        Leaflet, улицы, контуры и выбор объекта
vendor/leaflet/                   локальная библиотека 1.9.4 и её лицензия
vendor/lato/                      шрифт Lato (OFL), воспроизводимая загрузка — node scripts/vendor-lato.mjs
src/core/export.js                CSV с параметрами, адресами, процедурами и CO₂
tests/                            проверки алгоритма, модели, гео-функций, экспорта и реального среза
```

Приложение использует стандартные ES-модули JavaScript; Leaflet включён локально, поэтому установка npm-зависимостей не требуется. Файлы библиотеки, лицензия BSD-2-Clause и manifest находятся в `vendor/leaflet/`; воспроизводимая загрузка — `node scripts/vendor-leaflet.mjs`. См. [документацию Leaflet](https://leafletjs.com/reference.html) и [условия сервиса подложки OSM](https://operations.osmfoundation.org/policies/tiles/).

Цель подбора: максимальная сценарная выработка при ограничении бюджета. Сравниваются сортировка по выработке, сортировка по выработке на стоимость и дискретное динамическое программирование. В DP стоимость округляется вверх; результат сохраняется только в пределах настоящего бюджета модели. Выбирается лучший найденный вариант из трёх. Глобальный оптимум не гарантируется; дробная релаксация даёт верхнюю границу и позволяет оценить разрыв.

Проверяет польский интерфейс без кириллицы, кривую, процедуры, сохранение вариантов, снятие предела и предупреждение о концентрации, фильтр и сортировку таблицы, карту, экспорт, печать и мобильный экран; снимки сохраняются в `.preview/`.

`npm.cmd run registers` заново опрашивает реестры MSIP (около минуты, нужен сетевой доступ), `npm.cmd run pvgis` — эталон PVGIS. После обновления данных выполнить `npm.cmd run review` и `npm.cmd run benchmark`. `npm.cmd run context` заново загружает адресные точки и границы культурных парков MSIP и пересоздаёт `data/roof-context.json` (нужен сетевой доступ; без сети — `node scripts/fetch-context.mjs --from <папка с zip>`). `npm.cmd run review` пересоздаёт JSON и RU/PL CSV очереди проверки для стандартного плана. Ручные результаты сохраняйте в отдельном файле; автоматического импорта пока нет.

Проверка 0.6 от 26 октября: 31 тест; браузерный QA (включая размер текста и контрастную версию) без ошибок JavaScript; 390 px без горизонтальной прокрутки в обычной и контрастной версии; отчёт — одна страница A4 на PL и RU.

Проверка 0.5 от 26 октября: 31 тест проходит; браузерный QA в Chrome проходит без ошибок JavaScript; польский интерфейс без кириллицы на экранах «Plan», «Dane» и «Metodyka»; на ширине 390 px нет горизонтальной прокрутки; печатный отчёт — одна страница A4 на PL и RU.

Проверка ветки мониторинга (Daniel-blck, 26 октября): 28 тестов проходят, сборка создана. Проверены интегрирование энергии с пропусками, требования к денежному эффекту, формат импорта, происхождение примера, построение интерфейса RU/PL и USB-адаптер на имитации потока.
