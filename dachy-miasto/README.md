# Dachy Miasto

Работающий локальный прототип для конкурса Open Data App Kraków. Приложение подбирает портфель крыш под заданный бюджет, сравнивает три стратегии и показывает чувствительность результата к изменению допущений.

Это промежуточная версия. Интерфейс по умолчанию на русском; переключатель **RU / PL** вверху сохраняет выбор языка. Карта показывает улицы OpenStreetMap и контуры MSIP, поддерживает колесо мыши, перетаскивание и приближение выбранной крыши.

В версии 0.4 числовое объяснение связывает солнечное излучение с прогнозом электричества, мощностью и стоимостью выбранной крыши. В «Методике» описаны измерения и учёт наклона/теней в MONIT-AIR, а также сравнение большой крыши и более солнечного метра.

Новый экран «Мониторинг» принимает JSON записей, показывает график мощности и энергию без заполнения длинных пропусков. Доступны явно помеченный искусственный пример и чтение USB-стенда через Web Serial. Для координат импортированной PV появляется отдельный синий маркер. Денежный эффект требует измеренных потоков собственного потребления/экспорта и введённых цен. Настоящая городская установка пока не подключена; прошивка на оборудовании не проверена.

На карте можно включить сетевой городской слой OZE 2024 года: он включает PV, коллекторы и тепловые насосы, не содержит онлайн-выработки и не меняет допуск крыш к подбору. Его загрузка в текущей среде не проверена.

Карточка также отдельно показывает наличие геометрии и незавершённые проверки участка, владельца, адреса, охраны и PV. В разделе «Данные» доступна выгрузка до 15 крыш для ручной проверки. Все статусы остаются неподтверждёнными; [порядок проверки и источники](REVIEW_GUIDE.md).

## Запуск

Нужен Node.js 22 или новее. Зависимостей для установки нет.

```powershell
cd C:\Users\klim3\Desktop\dachy_miasta\dachy-miasto
npm.cmd run dev
```

Открыть **http://127.0.0.1:4173/** в браузере. Завершить сервер — `Ctrl+C`.

Из родительской папки можно запустить `START_DACHY.cmd`. HTML следует открывать через сервер: браузер загружает JSON, ES-модули и Worker.

## Что проверить вручную

1. При стандартном сценарии 5 млн zł появляются 6 крыш, около 1008,17 МВт·ч/год и сравнение с базовой стратегией.
2. Изменить бюджет, стоимость монтажа или покрытие площади: список и сравнение пересчитаются.
3. Навести курсор на карту и прокрутить колесо; переместить карту мышью. «Все крыши» возвращает общий вид, «Выбранные» показывает объекты плана.
4. Нажать на крышу на карте или в списке. Карточка обновится; выбор в списке приблизит объект. «Показать на карте» повторно приближает выбранную крышу. Исключить и восстановить объект.
5. Перейти в «Данные», найти объект по ID, открыть его карточку.
6. Открыть «Методика», проверить допущения и источники. Подробности качества алгоритма на основном экране свёрнуты, чтобы не перегружать интерфейс.
7. Выгрузить CSV или полный JSON сценария. «Отчёт PDF» открывает печать браузера; выбрать сохранение в PDF. Подписи CSV и отчёта соответствуют выбранному языку.
8. Переключить RU / PL: расчёты и положение карты сохраняются.
9. Выбрать крышу и прочитать блок «Откуда берётся прогноз»: входные поля и коэффициенты должны совпадать с параметрами и результатом. В «Методике» посмотреть объяснение наклона и сравнение условных крыш.
10. В «Мониторинге» открыть учебный пример: видна подпись об искусственных данных, график реакции на тень, денежный эффект отсутствует. Сохранить JSON и загрузить его обратно: пример сохраняет происхождение.
11. Для реальной записи использовать формат из `MONITORING.md`. Проверить период, пропуски, денежный эффект только при наличии потоков и цен. Установка с координатами показывается отдельным синим маркером; клик открывает запись.
12. Включить городской слой OZE: он требует сети; при ошибке показывается сообщение. Не считать все объекты слоя фотоэлектрическими установками и не трактовать их как подключённые к мониторингу.

Параметры, исключения и язык сохраняются только в текущем браузере. «Сбросить параметры» восстанавливает исходный расчёт и возвращает исключённые объекты.

## Данные и границы версии

- Извлечены 927 записей из исходного HTML; сохранён SHA256 источника. Дата первоначального среза неизвестна.
- Для всех 927 идентификаторов получена геометрия из официального MSIP, преобразованная сервером в EPSG:4326. Значения годового излучения совпали с исходным пакетом.
- Официальный сервис содержит 118 594 записи и описан как MONIT-AIR Atlas 2016. Полный город в приложение не загружен.
- Солнечные показатели и полезная площадь в расчётах пока остаются значениями исследовательского пакета; геометрия обогащена отдельно. В исходном пакете площадь округлена. Верификация геометрии не доказывает актуальность построек и установок.
- Собственность/управление зданием, охранный статус, несущая способность и наличие PV **не подтверждены**. Присвоение городским участкам унаследовано от макета и требует воспроизводимого пространственного соединения.
- Флаг зелёной кровли и название климатической инвестиции не являются инженерным заключением или доказательством установленной PV.
- Коэффициенты и затраты — изменяемый сценарий. Экономия денег, окупаемость, самопотребление, инженерная готовность и соответствие EED не заявляются.
- Географическое представление использует Leaflet 1.9.4 и улицы OpenStreetMap. Для загрузки новых фрагментов подложки нужен интернет; библиотека и данные крыш хранятся локально. При недоступности подложки отображается сообщение, контуры и расчёты продолжают работать. Если геометрии нет в пакете, доступна явно обозначенная схема.
- Выбор крыши показывает её географическое положение; это ещё не подтверждённый почтовый адрес или название учреждения.
- Срез и расчёты работают без MSIP и внешнего интернета. Условия дальнейшей публикации данных MSIP нужно проверить до внешнего размещения. На карте сохранена атрибуция OpenStreetMap.
- Панель с физическими датчиками не входит в основной объём проекта.

## Архитектура

```text
scripts/extract-reference.mjs     HTML → нормализованные записи + происхождение
scripts/fetch-msip.mjs            запросы к MSIP → геометрия + журнал верификации
src/core/model.js                физическая модель, стоимость, фильтрация
src/core/optimizer.js            стратегии, динамическое программирование, граница
src/worker.js                    подбор и сценарии без блокировки интерфейса
src/app.js                       точка входа
src/controller.js                состояние, события, Worker и экспорты
src/views.js                     интерфейс и пояснения
src/i18n.js                      русские и польские тексты
src/map.js                       Leaflet, улицы, контуры и выбор объекта
vendor/leaflet/                  локальная библиотека 1.9.4 и её лицензия
src/core/export.js               CSV с параметрами и ограничениями
tests/                          проверки алгоритма, экспорта и реального среза
```

Приложение использует стандартные ES-модули JavaScript; Leaflet включён локально, поэтому установка npm-зависимостей не требуется. Контрольные суммы JS/CSS проверены по официальной документации. Файлы библиотеки, лицензия BSD-2-Clause и manifest находятся в `vendor/leaflet/`; воспроизводимая загрузка — `node scripts/vendor-leaflet.mjs`. Подложка загружается браузером обычными запросами для текущего вида карты; массовая выгрузка и предварительная загрузка территории не выполняются. См. [документацию Leaflet](https://leafletjs.com/reference.html) и [условия сервиса подложки OSM](https://operations.osmfoundation.org/policies/tiles/).

Цель подбора: максимальная сценарная выработка при ограничении бюджета. Сравниваются сортировка по выработке, сортировка по выработке на стоимость и дискретное динамическое программирование. В DP стоимость округляется вверх; результат сохраняется только в пределах настоящего бюджета модели. Выбирается лучший найденный вариант из трёх. Глобальный оптимум не гарантируется; дробная релаксация даёт верхнюю границу и позволяет оценить разрыв.

## Проверки и сборка

```powershell
npm.cmd test
npm.cmd run benchmark
npm.cmd run review
npm.cmd run build
```

- Тесты включают сравнение 60 малых задач с полным перебором, единицы модели, округление, исключения, экспорт, геометрию и бюджеты на реальном срезе.
- Результаты восьми сценариев сохранены в `data/benchmark.json`.
- `dist/` — автономная статическая сборка. Её нужно обслуживать HTTP-сервером.
- `scripts/browser-qa.mjs` использует установленный Chrome на Windows и работающий локальный сервер. Проверяет основные действия, экспорт и мобильный экран, сохраняет снимки в `.preview/`. Путь браузера в скрипте зависит от компьютера.
- Дополнительно проверяются реальная загрузка улиц, колесо мыши, перетаскивание, сохранение положения карты при пересчёте, клик по крыше, переключение RU/PL и работа расчётов при блокировке подложки.

Повторное извлечение: `npm.cmd run extract`. Повторная загрузка геометрии: `npm.cmd run sources` (нужен сетевой доступ). После обновления источников повторить тесты и сравнение.

`npm.cmd run review` пересоздаёт JSON и RU/PL CSV очереди проверки для стандартного плана. Ручные результаты сохраняйте в отдельном файле; автоматического импорта результатов пока нет. Для браузерной проверки без внешних тайлов: `node scripts/browser-qa.mjs --offline` при работающем локальном сервере. Этот режим намеренно блокирует подложку и не проверяет загрузку улиц из сети.

Проверка 0.4 от 26 октября: 28 тестов проходят, сборка создана. Проверены интегрирование энергии с пропусками, требования к денежному эффекту, формат импорта, происхождение примера, построение интерфейса RU/PL и USB-адаптер на имитации потока. Браузерный запуск в текущей среде не завершён из-за падения GPU-процесса Chrome. Предыдущие скриншоты и `browser-qa.json` относятся к 0.2; сведения о неудачной попытке 0.4 — `.preview/browser-qa-attempt.json` и `.preview/browser-stderr.log`. Браузерный сценарий расширен проверками новых экранов; альтернативный адрес задаётся `--url http://127.0.0.1:4174/`.

## Следующая итерация

1. Пройти основной сценарий вместе с командой на русском и уточнить оставшиеся непонятные подписи.
2. Добавить подтверждённые адреса/названия учреждений, восстановить связь с актуальными муниципальными участками и явно показывать основание принадлежности.
3. Проверить 10–15 карточек по первоисточникам, смысл полезной площади, возраст данных и ограничения установки.
4. Уточнить расчёт и сравнения на проверенных объектах; протестировать результат с представителем целевой аудитории.
5. Зафиксировать функциональность 2 ноября, подготовить польскую версию и конкурсный комплект к 4 ноября. Физическая панель остаётся за пределами основного объёма.
